# 降本纪律（Token 优化必读）

> 来源：2026-08-16 体检趋势分析项目复盘。同类任务全程 ~1.2M tokens，实测 50–60% 可压缩。
> 本文件在技能执行时**强制生效**。

## 消耗归因（基准数据）

| 来源 | 占比 | 根因 |
|------|:---:|------|
| 调试循环 | 28% | 解析器/OCR 反复"dump→改→重跑"，缺小样本验证 |
| 大文件反复读取 | 24% | dataset_std.json(324K)/trend_analysis.json(324K) 被整文件 cat |
| 代码写入 | 19% | 终版 3454 行，实际写入约 2.5×（含重写） |
| 上下文累积 | 17% | 多轮会话历史线性膨胀 |
| OCR 输出 + 图片 | 12% | 25 页 OCR 文本 + 8–10 张截图验证 |

## 四条强制纪律

### 1. 小样本先行验证（省 ~14%）
- 解析新格式 PDF：**先打印 1 页坐标样本**（`get_text("words")` 按 y 聚合），人工确认列边界后再写/调解析器
- OCR 参数：先用**单页小图**验证 DPI/语言/纠错，有效后再全量
- 铁律：**不写一次性全量脚本，先写探测脚本**

### 2. 输出压缩（省 ~15%）
- 调试命令统一加 `| head -N` / `2>&1 | tail -N`
- 查 JSON 数据用 `python -c` 精准提取字段，**禁止整文件 cat/dump**
- 打印数据表只输出需要的列与行

### 3. 子代理隔离（省 ~22%）
- 大文件读取、格式探测、目录遍历交给 Explore/general-purpose 子代理
- 子代理独立上下文，只返回结构化结论（如"列边界：名称<195 | 值195-295 | 参考295-385"）
- 主线程不接触原始 dump

### 4. 验证收敛（省 ~5%）
- 中间迭代用 DOM 检查 / JS 单测（`node --check`）替代截图
- 截图仅做**最终版一次验证**
- 长任务分阶段推进，每阶段产物落盘，后续在新上下文继续

## 预期收益

叠加执行：同类任务 ~1.2M → ~0.5M tokens（-50~60%）。
