# OCR 方法学（扫描件 / 照片版）

> 适用：无文本层 PDF（扫描件）与照片 JPG。核心难点是中文项目名识别率低，但**数字/单位/参考范围识别可靠** → 用"参考范围反推"绕过项目名。

## 引擎与参数（macOS Vision）

```python
req.setRecognitionLevel_(1)          # accurate（高精度）
req.setUsesLanguageCorrection_(False) # 关闭纠错（纠错会把乱码改错）
req.setRecognitionLanguages_(["zh-Hans"])
# DPI：扫描件 200–300；渲染页码转 PNG 后经 Vision 识别
```

**关键参数经验**：DPI 180 起步，识别率不足再升 300；单语言 zh-Hans 优于 zh+en 混合；纠错开关在中文乱码场景必须关。

## 两种提取策略

### 策略 1：英文缩写直接映射（照片版，2015–2020）

照片版报告项目名乱码，但化验单常带英文缩写（ALT/AST/TP/ALB 等）：
- 维护 `ABBR_MAP`：`"ALT": "丙氨酸氨基转移酶(ALT)"`、`"TP": "总蛋白"`、`"HDL-C": "高密度脂蛋白胆固醇"` 等（见 `extract_2015_2020.py` 顶部）
- 命中缩写后，在 y 邻近 ±3 行内找数值/参考范围/单位
- 注意：缩写可能误命中其他行（如 `K` 命中年份"2015"），必须用 PLAUSIBLE_RANGES 校验

### 策略 2：参考范围反推（扫描件，2022）

- 用 `dataset_std.json`（已有年份）建反向索引：`指标 → 参考范围列表[(lo,hi)]`
- OCR 行中提取参考范围字符串（`4.00-5.50` / `<200` / `>0.4`），与索引容差匹配（±15% 或 ±0.5）
- 参考范围**前**的最近数字作为值
- 中文项目名完全乱码也不影响（2022 报告 16 页仅提取 15 项核心指标）

## 合理性校验（必须）

```python
PLAUSIBLE_RANGES = {
    "空腹血糖": (2, 30), "糖化血红蛋白": (3, 20),
    "尿酸": (50, 1000), "肌酐": (10, 1000),
    "丙氨酸氨基转移酶(ALT)": (1, 1000), "钾": (1, 10), ...
}
```
- 数值超出范围 → 拒绝（实例：OCR 提取 `GGT -1.0`、`MCV 4.0`、`血小板计数 9.0` 均被过滤）
- 单位不匹配 → 拒绝（如 OCR 给出 `%` vs 指标标准 `μmol/L`）
- 同年已有数据 → 跳过（避免覆盖可靠来源）

## 已知局限

- 照片版（手机横拍）需先旋转校正：宽>高 → `img.rotate(-90, expand=True)`（顺时针 90°）
- Vision 对照片中文识别率 <50%，2015–2020 每年仅能提取 11–28 项
- OCR 数据**不参与显著变化/趋势判定**，仅图表展示（灰色 Ⓞ 标注）；报告注明"OCR 提取，供历史参考"

## 增强方向（可选）

- 腾讯云 OCR 表格识别（`tencentcloud-ocr-recognizetableaccurate`）可提升照片版准确率，但需联网+密钥，与"全本地化"冲突——仅在用户明确接受云端时启用
